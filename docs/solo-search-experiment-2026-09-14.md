# solo-search 実験報告

更新日: 2026-09-14

この文書は `docs/solo-search-plan-2026-09-14.md` に従った実装、判断、検証結果を記録する。基準コミットは `8db100a412568e12f1dadd239611c349e41bc353` である。着手時の未コミットファイルは `.claude/` と計画書だけであり、どちらも変更または削除していない。

## 2026-09-14 実装開始

新しい実行時エンジンとして `src/ai/solo-search.js` と `src/ai/solo-value.js` を追加した。探索は深さ3、既定のBeam Width 22、割引率0.99とし、各初手の生存する最良経路を確保する。実際の10連鎖以上だけを累積報酬へ加え、死亡時には一度だけ-4を加える。モデルは配置後盤面から始まる将来価値を返すため、その手で発生した報酬をモデル入力側で重ねていない。

モデル入力は、列を先、下段を先に並べた6列×14段×5状態のone-hot 420要素と、配置後にまだ見えているNEXT2の18要素を合わせた438要素に固定した。MLPは438-64-32-2、ReLU、float32である。現在手、通算得点、turn、隠れたツモは入力しない。

評価器では、予定手数を死亡後も分母へ含めるU1000、10+から14+の発火回数、200手区間の連発率、60手以内の再発火率、大連鎖がない最長手数、死亡率、初回10+までの手数を実イベントから集計する。ゲームseedを単位とする対応付きbootstrapも実装した。手作りイベント列による9件の専用テストはすべて成功した。

ツモ列は `solo-search-20260914/{train,dev,test,latency}/{index}` という名前から既存の `src/core/randomizer.js` で生成した。train 64ゲーム、dev 64ゲーム、test 128ゲーム、latency 64ゲームを別ファイルへ保存し、各ファイルのSHA-256をmanifestへ記録した。これらの生成物は大量データと同じくGitの対象外にした。

## 2026-09-14 JAX盤面処理の最初の一致確認

JAX版は `(6, 14)` のuint8盤面を使い、現在のJavaScript実装に合わせて、13段の保存、12段の消去判定、0始まりの `(2, 11)` に配置した時点での死亡、横置きの個別落下、同色組の合法手重複除去、全消し、連鎖得点を実装した。ルールは古い仕様書から移さず、`src/core/fast-board.js` が返す結果を比較対象にした。

最初のローカル確認では、ランダムな合法軌跡から得た20盤面について、4色の16組とすべての合法配置、合計6,160配置を比較した。配置後盤面、死亡、連鎖数、得点、全消しはすべて整数で一致し、連鎖処理の上限超過はなかった。JAX 0.11.1のCPU実行で、初回コンパイルと最初のbatchは0.44秒、以降は合計0.40秒、約15,600配置/秒だった。この値はGPU探索の速度ではない。

空盤面における旧v13標準設定の探索は、このMacで1手約210msだった。固定train seed 64ゲームの初期軌跡は6個のNode.js Workerで収集中である。初期データの条件である10連鎖以上100件を満たすかは、収集終了後の実イベントから判定する。

着手時点ではKaggleへ未投入だったため、短い事前ジョブでJAX/CUDAデバイス、JS fixtureとの一致、盤面解決・MLP・探索全体の速度、出力回収、回収したstateを入力にした再開を順に確認した。投入直前には `kaggle quota` を再実行し、認証と残りGPU枠を確認した。

## 2026-09-14 初期学習・GPUシミュレーション

初期v13軌跡は64ゲームから55,444件を作り、53,316件を学習、2,128件を検証へ分けた。10連鎖以上の発火は765件、10連鎖以上を含むゲームは63件で、初期教師の最低条件を満たした。Kaggleの学習は11 epochで完了し、最良検証損失は0.42453184723854065だった。JAX 0.7.2、T4 2枚を使い、学習時間は8.27秒だった。ブラウザ用モデルのSHA-256は `f005aa1689f2092a202571ce270a2d6849a746baf7e7c88e260b1e36b38e1077` である。

smoke v4では10,000盤面・3,080,000 fixtureケースの一致を確認し、smoke v5では `state.npz` のSHA-256一致を含む回収後の再開を確認した。その後の本番JAXシミュレーションはdev 64ゲーム×1,000手、Beam 32で2枚のT4を使い、全64,000手を完了した。所要時間は1,485.4秒、死亡0、最高連鎖1、10連鎖以上0件だった。これは学習モデルだけを使った結果であり、学習損失が下がったことだけでは大連鎖能力を示さないことが分かった。回収したトレースのSHA-256は `e6ed9c604537eca5c059ae6e1f811552afd4b429c68111a2a60e783afa1ad717` である。

この結果を受け、実行時の `solo-search` に盤面構造の事前評価を加え、学習モデルは長期価値と死亡確率の残差として使う構成にした。旧vシリーズを実行時に呼ばず、事前評価は `src/ai/solo-search.js` 内で完結させた。固定dev 4ゲーム×300手では、Beam 22がU1000 6.0417、10連鎖以上6回、11連鎖以上4回、12連鎖以上1回、最高12、死亡0で、探索時間の中央値170.96ms、p95 283.66msだった。Beam 32はU1000 4.375、10連鎖以上4回、11連鎖以上3回、12連鎖以上2回、最高12、中央値351.93ms、p95 559.23msだった。したがってブラウザの既定値はBeam 22とした。4ゲームのため採用条件を満たしたとは判定していない。

同じ4ゲーム×300手で旧v13標準も測ると、U1000 14.7917、10連鎖以上14回、11連鎖以上9回、12連鎖以上5回、13連鎖以上1回、死亡0、中央値353.22ms、p95 493.77msだった。この小規模比較では新系統は速度面で有利だが、連鎖能力は旧v13を上回っていない。したがって旧v13に対する性能改善や置換成功とは報告せず、新系統の実装・モデル・選択可能なUIを検証する結果として扱う。

モデル推論のJS/JAX比較は400件で最大絶対誤差1.43e-6、許容値比0.00278だった。一方、JAX評価カーネルはモデルだけを使い、ブラウザ側は構造事前評価を含むため、探索行動は一致しない。この差は実装不一致として隠さず、モデル推論の一致と最終ブラウザ探索の評価を分けて記録する。

固定test 128ゲーム×1,000手の重い評価は、`ikakun624/puyoai-solo-search-evaluation` としてKaggle T4へ投入し、2枚のT4、JAX 0.7.2で1,792.65秒に完了した。128,000手を全て実行し、死亡0、イベント19、10連鎖以上0件、最高連鎖1だった。モデルSHA-256は `f005aa1689f2092a202571ce270a2d6849a746baf7e7c88e260b1e36b38e1077`、test seed SHA-256は `ef260983aabcc50f8f80ed45d1b806801e5dc6a729062817603972b8ab9cb7f1`、回収したトレースSHA-256は `422ba0bc2f156a82606711be6c5f52fd338e38c1afd9859a3f3755e4eaccd831` で、いずれもローカル再計算と一致した。この結果も学習モデル単体のJAX経路であり、構造事前評価を含むブラウザ経路の性能を直接表さない。

最終確認では `node --test` の118件が全て成功し、JavaScript/Pythonの構文確認と `git diff --check` も成功した。Safariのローカルppsim2を再読み込みし、設定画面で `Solo Search` とBeam 22を確認した後、AI一手が `PuyoAI Solo Search / LEFT:4 / 0連 / 185ms` と実行された。ブラウザ用モデルは `models/solo_value.web.json` に置き、Kaggle回収モデルと同じSHA-256である。

## 2026-09-14 追加反復の停止点

GPU枠を追加消費する前に、固定dev seedの短いCPUスクリーニングを行った。学習モデルだけでは大連鎖を選べなかったため、旧v13を実行時に呼ばずに、`solo-search` 内で実連鎖の段階的な配置価値を加えた。小連鎖を抑え、10連鎖以上を重くする値と、既存の盤面構造評価を組み合わせ、学習モデルの長期価値補正は小さくした。

4ゲーム×300手ではBeam 22・モデル補正30の候補がU1000 18.125、Beam 32が15.208だった。より再現性を見るため同じ条件をdevの16ゲームへ拡張し、Beam 32候補はU1000 15.9896、10連鎖以上13.125/1000手、11連鎖以上6.4583/1000手、12連鎖以上3.75/1000手、13連鎖以上0.625/1000手、14連鎖以上0.625/1000手、最高15連鎖、死亡率0だった。比較対象の旧v13標準（同じdev 16ゲーム×300手）はU1000 11.7188、10連鎖以上9.7917/1000手、11連鎖以上5.4167/1000手、12連鎖以上2.0833/1000手、13連鎖以上0.2083/1000手、死亡率0だった。この区間では新系統候補が上回ったが、まだ固定test 128ゲームでの採用判定はしていない。

この時点でユーザー指示により反復を停止した。停止時点のソースは `src/ai/solo-search.js`、候補の測定結果は `training/solo_search/artifacts/evaluation/dev-solo-turnprior-model30-beam32-16x300.json`、旧v13比較は `training/solo_search/artifacts/evaluation/dev-v13-16x300.json` に保存している。追加反復の直後に対象テスト9件、構文確認、`git diff --check` を実行し、すべて成功した。Beam 32は既定値へ変更せず、ppsim2の選択可能状態も変更していない。Kaggleへの新規投入とモデルの正式置換は次回再開時に行う。

## 2026-09-14 GPU評価経路の再開

再開後もゴール機能は使わず、判断と実装はメインセッションで続け、長時間の実行監視だけをLunaへ分離した。ブラウザ候補とGPU評価の条件差をなくすため、`training/solo_search/jax_structure.py` に盤面構造評価と実連鎖の段階的価値を実装し、`jax_search.py` の累積値、死亡確率、モデル補正30をブラウザ版へ合わせた。旧v13の実行時コードは呼ばない。

ローカルJAX CPUで、Beam 22は固定dev 1ゲームの先頭20手、Beam 32は先頭2手を照合した。JS/JAXの選択手と各初手の探索スコアはすべて一致し、最大探索スコア誤差はそれぞれ約8.91e-6と7.19e-6だった。モデル出力の最大絶対誤差も9.54e-7以下だった。Kaggle入力にはJAX実装各ファイル、モデル、固定testツモを含め、モデルSHA-256 `f005aa1689f2092a202571ce270a2d6849a746baf7e7c88e260b1e36b38e1077` とtest seed SHA-256 `ef260983aabcc50f8f80ed45d1b806801e5dc6a729062817603972b8ab9cb7f1` を再確認した。

GPU投入前の比較用として、固定testの先頭32ゲーム×16手をJS版Beam 32で実行し、全512手、死亡0、最高1連鎖だった。短すぎて大連鎖性能を測る区間ではなく、GPU smoke回収後に行動列を照合するための基準である。Kaggle CLIはこの時点でOAuth設定を認識しているが、`api.kaggle.com` のDNS解決に失敗しており、5分間隔で接続復旧を監視している。
